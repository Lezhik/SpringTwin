# 005-generic-type-extractor — Реализация

## Статус: pending

## Описание

Реализация `GenericTypeExtractor` для извлечения типов из generic-сигнатур байткода.

## Классы и методы

### `spring.twin.scan.GenericTypeExtractor`

**Тип:** final утилитный класс

**Реализация:**

- Приватный конструктор — предотвращает инстанцирование

- `static Set<String> extractTypes(String signature)` — если `signature` == null или пустая, возвращает пустое множество. Иначе сканирует строку сигнатуры, извлекая все вхождения `L<internal_name>;`, пропуская формальные параметры типа (идентификаторы до `:`). Каждый найденный внутренний тип конвертируется через `FqcnNormalizer.fromInternalName()`. Примитивные дескрипторы пропускаются. **Метод должен быть аннотирован Javadoc на английском языке.**

- `static Set<String> extractTypeNames(String typeSignature)` — аналогично `extractTypes`, но предназначен для одной type-сигнатуры (не полной сигнатуры класса/метода). Обрабатывает `L...;` с возможными вложенными `<...>`. Извлекает все типы включая generic-параметры. Использует `FqcnNormalizer.fromInternalName()` для конвертации. **Метод должен быть аннотирован Javadoc на английском языке.**

## Логика работы

1. Сигнатура сканируется посимвольно
2. При обнаружении `L` — собираются символы до `;` как внутреннее имя класса
3. При обнаружении `<` — начинается область generic-параметров, типы внутри также извлекаются
4. При обнаружении `T` — формальный параметр типа, пропускается до `;`
5. Примитивные дескрипторы (`I`, `J`, `B`, `S`, `C`, `F`, `D`, `Z`, `V`) пропускаются
6. Массивы (`[`) пропускаются, базовый тип извлекается
7. Все найденные внутренние имена конвертируются через `FqcnNormalizer.fromInternalName()`
8. Результат — множество уникальных FQCN
